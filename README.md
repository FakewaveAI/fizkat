# ФизКат — система учета транспорта в парке
консольный учет парка: техники и вещей на балансе

## Сборка и запуск

Откройте папку проекта в терминале и выполните там эти команды:
```
cmake -S . -B build
cmake --build build
./build/fizkat
```

После этого проект запущен, команды можно вводить в терминал (по одной в строке).
Программа для выхода - `quit`. Если ошибок в команде нет, то при необходимости будет выведен ответ.
Иначе будет выведена ошибка, ошибка печатается как `error: <текст ошибки>`, программа продолжает работу.

## Команды

| Команда | Что делает |
|---|---|
| `add scooter id name energy ease` | добавить электросамокат, указав новый `id`, `name`, `energy` и `ease`; предварительно проходит техосмотр |
| `add bike id name ease` | добавить велосипед, команда аналогичная электросамокату без энергии |
| `add ebike id name energy ease` | добавить электровелосипед, команда аналогичная электросамокату |
| `add golf_cart id name energy ease` | добавить гольф-кар, команда аналогичная электросамокату |
| `add helmet id name` | добавить шлем, указав новый `id` и `name` |
| `add dock id name energy` | добавить док-станцию, команда аналогичная шлему, но дополнительно имеющая `energy`|
| `energy` | дневные затраты энергии (сумма, вещественное число с 1 знаком после точки) |
| `novice` | список транспорта для новичков (простота ≥ 6), гольф-кар не входит ведь для него нужны права; отсортирован по id |
| `list` | список транспорта и вещей, отсортированных по `id` |
| `focus id` | поставить на витрину объект с ID: `id`|
| `show_focus` | выводит описание объекта на витрине; если не ставили — `empty`, если удалили — `removed` |
| `remove id` | удаляет из списка объектов объект с ID: `id` |
| `last` | выводит описание последнего добавленного транспорта; если ничего не добавляли - `empty`; если удалили последний транспорт — `removed` |
| `quit` | завершить выполнение программы |

Параметры: `id` — инвентарный номер (строка), `name` — имя (одно слово),
`energy` — суточный расход энергии в кВт·ч (≥ 0), `ease` — простота для новичка (целое число от 1 до 10).
Транспорт проходит техосмотр, если в имени нет подстроки `broken` (в любом регистре).

## Схема наследования

```
InventoryItem (абстрактный)                 EnergyConsumer (абстрактный)
  └── ItemBase (абстрактный)                       │
        ├── Transport (абстрактный)                │
        │     ├── Bike                             │
        │     └── ElectricTransport (абстрактный) ─┤  множественное наследование
        │           ├── ElectricScooter            │
        │           ├── ElectricBike               │
        │           └── GolfCart                   │
        └── Thing (абстрактный)                    │
              ├── Helmet                           │
              └── Dock ────────────────────────────┘  множественное наследование
```

## Классы

| Класс | Файл | Наследуется от | Абстрактный? | Что делает |
|---|---|---|---|---|
| `InventoryItem` | `Inventory.hpp` | — | да | интерфейс элемента инвентаря; чисто виртуальные методы: `getID`, `getName`, `type`, `description`; ответы на вопросы: `energy()` и `isForNovice()`; виртуальный деструктор |
| `EnergyConsumer` | `Inventory.hpp` | — | да | дополнительный интерфейс для потребителя энергии; чисто виртуальный метод `dailyEnergy()` |
| `ItemBase` | `Inventory.hpp` | `InventoryItem` | да | дополнительно `id` и `name` для элемента инвентаря с возможностью узнать их; проверяет что непустые|
| `Transport` | `Transport.hpp` | `ItemBase` | да | простота использования, правило подходимости для новичка (простота ≥ `cNoviceThreshold`), общее описание (`description`) транспорта через виртуальный метод `type()` |
| `Bike` | `Transport.hpp` | `Transport` | нет | определяет свой `type()` |
| `ElectricTransport` | `Transport.hpp` | `Transport`, `EnergyConsumer` | да | хранит энергию и реализует `dailyEnergy()` через нее, к описанию добавляет затраты энергии, `energy()` возвращает что он `EnergyConsumer` |
| `ElectricScooter` | `Transport.hpp` | `ElectricTransport` | нет | определяет свой `type()` |
| `ElectricBike` | `Transport.hpp` | `ElectricTransport` | нет | определяет свой `type()` |
| `GolfCart` | `Transport.hpp` | `ElectricTransport` | нет | определяет свой `type()` и переопределяет `isForNovice()` на константный `false`; в описание добавляет что нужны права |
| `Thing` | `Things.hpp` | `ItemBase` | да | общее описание вещей |
| `Helmet` | `Things.hpp` | `Thing` | нет | определяет свой `type()` |
| `Dock` | `Things.hpp` | `Thing`, `EnergyConsumer` | нет | определяет свой `type()`, хранит энергию и реализует `dailyEnergy()` через нее, к описанию добавляет затраты энергии, `energy()` возвращает что он `EnergyConsumer`  |

Виртуальное наследование не понадобилось, ведь ромбов нет (`EnergyConsumer` ни через кого не наследуется). Множественным наследованием обладают `ElectricTransport` и `Dock` (эти классы одновременно элемент инвентаря и потребитель энергии).
Парк хранит `vector<shared_ptr<InventoryItem>>` и команды работают только через указатель на `InventoryItem`.
`energy()` - возвращает `nullptr` если не потребитель энергии и `energy` в таком случае не прибавляет энергию. `novice` использует `isForNovice`.
Таким образом `dynamic_cast` и проверки типа не используются.

## Перегрузка операторов (`Inventory.hpp/.cpp`)

- `operator<<` — выводит `id` и `name`
- `operator<` — сравнивает `id` и используется при сортировке
- `Report::operator+=` — накапливает энергию и количество позиций на балансе (возвращая ссылку на себя), используется для нахождения дневной энергии

## Умные указатели

| Указатель | Где | Почему он |
|---|---|---|
| `unique_ptr` | `doAdd()` в `main.cpp` техника создаётся через `std::make_unique` и передаётся по значению в `Fleet::addTransport` / `Fleet::addThing` | единоличное владение новой единицей до техосмотра; если техосмотр или проверка id бросили исключение то параметр уничтожится при выходе из метода вместе с объектом; иначе переходит в парк (перемещается в `shared_ptr`); удобно что не надо думать о том удалился объект или нет|
| `shared_ptr` | `Fleet::items_` — `vector<shared_ptr<InventoryItem>>` | `unique_ptr` перемещается в `shared_ptr` (после `push_back(std::move(...))`); если `removeId` удалит последнего владельца, то объект уничтожится сам; `shared_ptr` чтобы `weak_ptr` мог наблюдать за ним |
| `weak_ptr` | `Fleet::display_` и `Fleet::lastTransport_` | сам не влияет на продолжительность жизни объекта, но при этом позволяет знать существует ли еще объект через `lock()` |

Сырые указатели существуют только для временных списков (например в `sortedItems()` для вывода). `new` и `delete` в проекте не используются.

## Исключения (`Errors.hpp`)

Я создал класс `FleetError` - общий класс ошибок, от которого будут наследоваться конкретные ошибки и который мы будем ловить в `main.cpp`.
`error: ` печатается в `main.cpp` после `catch`.

| Исключение | Когда бросается |
|---|---|
| `FleetError` | общий базис (от `std::exception`), ловится один раз в `main`|
| `InspectionRejected` | в случае если транспорт не прошел технический осмотр |
| `ParseError` | команда набрана неправильно (кроме того даются подсказки как написать правильно) |
| `IncorrectArgument` | пустой ID, энергия или простота не в нужных диапазонах |
| `UnknownID` | `remove` или `focus` с несуществующим ID |
| `DuplicateID` | если пытаемся добавить объект по уже существующему ID |

Ошибки стандартной библиотеки:
в `main.cpp` есть функции перевода строки в `double` и в `int`, там ловятся стандартные исключения `std::stoi/std::stod` и позже через `catch` отдаются `ParseError`.
Все проверки, которые могут бросить исключение, выполняются до изменения парка - поэтому ничего не ломается.


## Шаблоны (`Registry.hpp`)

| Шаблон | Что делает | Где используется |
|---|---|---|
| `Registry<T, MaxSize>` | шаблонный класс: журнал на `MaxSize` последних записей типа `T`; методы: узнать размер и элемент по индексу, `add` - создать новую запись, `operator<<` - выводит каждую запись; как только размер больше `MaxSize` хранятся только последние `MaxSize` элементов | журнал техосмотров в `ServiceCenter` на 16 записей|
| `makeReport(container)` | через `Report::operator+=` собирает report по любому контейнеру указателей на позиции инвентаря | `Fleet::report()` |
| `conditionSelect(container, condition)` | отбирает из любого контейнера указателей позиции, которые подходят под условие и возвращает `vector<const InventoryItem*>` для последующего вывода | `Fleet::sortedItems()`, `Fleet::noviceItems()`, два разных типа контейнеров `vector<shared_ptr<InventoryItem>>` и `vector<const InventoryItem*>`|

`conditionSelect(container, condition)` нужно отдельно для `list` чтобы выбрать все элементы и добавить их в вектор сырых указателей и для `novice` чтобы отобрать только то, что для новичков.

## Креатив

Я добавил транспорт гольф-кар (класс `GolfCart`, `add golf_cart`) - он тратит энергию, но он в любом случае не для новичков и в описании говорит, о том что нужны права.
Кроме того я добавил команду вывода последнего добавленного транспорта (команда `last`): для этого я просто добавил указатель `weak_ptr` на последний добавленный транспорт.
